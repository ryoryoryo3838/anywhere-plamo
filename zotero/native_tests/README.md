# Official Zotero reader acceptance (Linux)

From the repository root run `TMPDIR="$HOME/.hermes/cache/scratch" python3 -B zotero/native_tests/run.py` (the scratch directory must already exist). Requires `bwrap`, Zotero Flatpak **10.0.8**, and its installed Freedesktop 25.08 runtime. No display, live bridge, model, or sign-in required. Each run builds a fresh XPI from all files in `zotero/addon` using `zotero/build.py` and prints its SHA-256.

The launcher starts the installed application in a new network, process, and filesystem namespace. Only the new scratch directory, app/runtime files, and system passwd/group are mounted. A mock bridge inside the namespace validates a fresh bearer token and the actual source PDF; no real profile, token, or job is accessible. The host-window test driver is appended to a disposable copy of the application's `omni.ja` (the reader frontend and plugin are not patched).

The two-page fixtures use explicit English markers (`Original page …`, `Translated page …`). This tests the native reader integration, **not** translation quality or the live translation worker. The mock releases two single-page PDFs separately while the job is running. Page one must become translated while page two still contains its source text. The driver then zooms and scrolls across the page boundary. When page two arrives, it checks that the right reader and inner iframe documents, visible page-one node, canvas and pixels, zoom and scroll survive. A native proxy can expose translated glyphs or rendered text; a canvas overlay can set `data-anywhere-plamo-page="N"` on the PDF.js page or its child **after painting** (one-based). Only then can the mock release the final PDF. The driver selects and highlights final translated text and verifies that the same highlight reopens without modifying the source.

The printed evidence directory contains the XPI, `result.jsonl` (UI actions, measurements, annotation identity and result), `requests.jsonl` (authenticated requests/statuses, no token), and `native.log` (Zotero/Gecko errors). Success requires exit 0, a `PASS` record, successful authentication, and release of both distinct jobs. Each run prints a request inventory. The first job must fetch exactly `pages/1.pdf`, `pages/2.pdf`, then `document.pdf`; reopening the completed job must fetch only `document.pdf`. Requests to `preview.pdf` return 404 and fail the run. A failure names the first incomplete check; subsequent checks did not run. Scratch contains a disposable Zotero database and dummy token; do not publish the whole directory.
